# P0 Evaluation Cases

1. 上传正常 CSV，计算某列总和。
2. 上传正常 Excel，计算某列平均值。
3. 按地区分组统计销售额。
4. 找出销售额 Top 5 产品。
5. 按日期分析销售趋势。
6. 识别明显异常值。
7. 用户问题中指定不存在的字段，Agent 应提示字段缺失。
8. 上传空文件，Agent 应明确报错。
9. 数值列存在文本脏数据时，Agent 不应直接给出错误计算结果。
10. 用户问题信息不足时，Agent 应要求补充，而不是猜测。



# P1 Evaluation Cases

## 图表生成
1. 根据时间序列生成折线图。
2. 根据类别占比生成柱状图。
3. 根据两个数值字段生成散点图。
4. 用户指定图表类型时正确生成。
5. 数据不适合画图时给出提示。

## 多文件分析
6. 合并两个字段一致的 CSV。
7. 合并两个 Excel 文件。
8. 两个文件字段名称略有差异时提示映射问题。
9. 对两个文件做同比分析。
10. 对两个文件做分类对比。
11. 文件之一为空时正确处理。
12. 文件结构不一致时不给出错误结论。

## 历史对话
13. 用户追问“刚才哪个地区最高”，Agent 能基于前文回答。
14. 用户追问“那最低的呢”，Agent 能保持上下文。
15. 用户修改筛选条件后重新分析。
16. 用户更换指标后继续分析。
17. 用户上传新文件后，Agent 不混用旧数据。
18. 长对话后仍能引用正确分析结果。
19. 用户前后问题冲突时能识别。
20. 历史上下文不足时要求重新提供信息。



## Bad Cases

### BC-01 缺少字段
输入：
上传 sales.csv，提问“按利润率排序”，但文件中没有 profit 字段。

预期行为：
Agent 不应猜测字段，应提示缺少相关字段。

通过标准：
明确指出缺失字段，且不返回伪造分析结果。

### BC-02 空文件
输入：
上传空 CSV。

预期行为：
Agent 停止分析并提示文件为空。

通过标准：
不调用后续分析工具。

### BC-03 数据类型异常
输入：
sales 列本应是数值，但其中混入 "abc"。

预期行为：
Agent 识别数据类型问题并提示清洗或修正。

通过标准：
不得直接给出错误统计结果。

### BC-04 问题含糊
输入：
“帮我看看这个数据有什么问题。”

预期行为：
Agent 先做基础检查，或要求用户明确分析目标。

通过标准：
不能凭空下业务结论。

### BC-05 工具选择错误
输入：
用户问“销售额趋势如何”，但 Agent 错选了分组统计工具。

预期行为：
评测应将该 case 判为失败，并记录工具选择错误。

通过标准：
必须调用趋势分析相关工具才算通过。
