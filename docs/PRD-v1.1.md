# 数据分析 Agent PRD v1.1

## 1. 背景

业务人员经常需要对 CSV、Excel 等数据进行统计、对比、趋势分析和异常排查。固定脚本只能处理预设流程，遇到不同问题时需要重新修改代码；普通聊天模型又无法稳定完成真实数据读取、工具调用和多步分析。

因此，本项目计划实现一个数据分析 Agent，让用户通过自然语言提出分析需求，由 Agent 自动选择工具完成数据分析并输出结论。

## 2. 用户故事

作为业务人员，我希望上传 CSV 或 Excel 数据后，通过自然语言完成统计、对比、趋势和异常分析。当数据不满足分析条件时，我希望 Agent 能指出问题并提示需要补充或修改的数据。

## 3. 功能清单

### P0：必须实现

- 上传并读取 CSV / Excel 数据。
- 根据自然语言问题选择分析方式。
- 支持基础统计、分组对比、趋势分析和异常识别。
- 输出分析结果，并在数据或字段有问题时给出提示。

### P1：后续增强

- 自动生成图表。
- 支持多文件分析和历史对话。

### 明确不做

- 不做机器学习预测和复杂建模。
- 不自动修改原始数据。
- 不执行任意 Python 代码。

**运行约束**

- MVP 仅支持 CSV / XLSX。
- 单文件大小 ≤ 20MB。
- 暂不支持 PDF、图片和超大数据集。

## 4. 技术架构

- 用户上传 CSV / XLSX 文件并提出自然语言分析问题。
- 系统首先校验文件格式、大小和基本可读性。
- 数据处理模块读取文件，并提取字段、数据类型、缺失值和基础摘要等信息。
- Agent 根据用户问题和当前数据状态选择合适的分析工具。
- 分析工具执行基础统计、分组对比、趋势分析或异常检测，并返回结构化结果。
- Agent 根据工具结果判断是否需要继续分析；如果信息已足够，则生成最终结论。
- 系统限制单次任务的最大执行轮数，避免异常循环。
- 系统记录模型调用、工具调用、执行结果、异常、耗时和成本，方便调试和评测。

### 4.1 受控的多步 Agent 流程（v1.1）

- Agent 支持受控的多步分析流程。
- 每一轮由 LLM 根据用户问题、当前 Agent 状态以及前一步工具返回结果，决定继续选择后续分析工具或结束任务。
- 工具负责数据读取与真实计算；LLM 不直接计算或编造分析结果。
- 工具返回的结构化结果作为 observation 回填给 LLM，供下一轮决策使用。
- 单次任务设置最大执行轮数 `max_iter`。达到上限后必须停止，不得继续调用工具。
- 每轮记录 `iteration`、`tool_call`、`tool_result` / `observation`；任务结束时记录 `stop_reason`。
- `stop_reason` 至少能够区分：已生成最终答案、达到 `max_iter`、需要用户补充信息和执行错误。
- v1.1 仅增加 Agent 执行机制，不改变 P0 / P1 功能范围，也不引入 RAG、Memory 或 Multi-Agent。

## 5. 评测指标

- P0 case：10 条，覆盖基础统计、分组、趋势、异常识别和异常输入，详见 `tests/eval_cases.md` 中的 `P0 Evaluation Cases`。
- P1 case：20 条，覆盖图表、多文件分析和历史对话，详见 `tests/eval_cases.md` 中的 `P1 Evaluation Cases`。
- Bad case：至少 5 条，详见 `tests/eval_cases.md` 中的 `Bad Cases`。
- 评测脚本路径：`tests/eval_agent.py`
- 运行方式：`python tests/eval_agent.py`
- P0 case 通过率 = 100%
- 整体任务结果准确率 ≥ 85%
- 异常输入识别率 ≥ 90%
- 单次分析平均响应时间 ≤ 30 秒
- 单次分析成本 ≤ 0.5 元

## 6. 里程碑

- M1：跑通 P0 核心链路，完成文件上传、自然语言分析、基础统计/分组/趋势/异常分析和结果输出。
- M2：补充 P1 功能、日志与评测脚本，完成图表生成、多文件/历史对话能力和 20 条样本评测。
- M3：集中处理 bad case，优化工具选择、异常输入处理和结果准确率，并完成项目复盘。
- 保存评测结果、运行配置、工具调用日志和 bad case 复盘记录，确保他人可以复现评测过程。

## 7. 风险登记

- 数据格式异常 → 输入校验与错误提示。
- 工具选择错误 → 固定工具集合 + bad case 优化。
- LLM 错误解释结果 → 强制基于工具结果生成结论。
- 大文件导致延迟过高 → 限制文件大小和分析范围。
- P1 功能导致成本膨胀 → 控制上下文和调用次数。
- 对应失败场景详见 `tests/eval_cases.md` 中的 `Bad Cases`。
